# 직전 main 통신 동작 복원

2026-10-24 사용자 요청으로 최신 main `cf18a2e`와 첫 번째 부모인 직전 main
`ed7eca9`(2026-10-15)를 비교하고, 통신 관련 변경만 직전 main에서 복원했다.

차이는 상태 UDP의 Auto 확인을 송신 필수 조건으로 추가한 변경과 Q 전환 방식이었다.
현재 로컬 실행에서 Competition Vehicle Status 수신은 0건이었고, 이 조건 때문에
Safety 명령이 있어도 제어 송신이 중단됐다.

복원 범위는 `morai_interface_pkg`, 중앙 UDP 계약과 global_path_demo 예외,
두 개발 통합 launch의 상태 수신기 연결 및 관련 문서·테스트다.
센서 수신·명령 패킷의 직렬화 형식은 두 main 사이에 차이가 없었다.
지도·공유 메시지·인지·Localization·Planner·Controller·Safety 구현은 최신 main을 유지한다.

로컬 개발 실행은 새 Safety 명령을 받으면 Auto 명령(`ctrl_mode=2`, `cmd_type=1`)을
송신한다. 별도 차량 상태 수신을 송신 전제조건으로 사용하지 않는다.
MORAI 창에서 Q를 한 번 누르면 송신 중단을 유지하고, 다시 누른 뒤 0.5초가 지나면
새 명령 송신을 재개한다. Q 방식은 실제 모드를 읽는 기능이 아니며 창 포커스와
키 입력에 의존하는 직전 버전의 동작이다.

명령 생성 시각 검사, NaN/범위 검사, 조향 변환 승인, 기본 dry-run 및
Safety 최종 명령만 소비하는 경계는 유지한다. 이전 비영점 명령을 타이머로 반복하지 않는다.

전체 catkin 빌드, 통신 패키지·bringup 테스트 115개(오류·실패 0), 중앙 계약/다이어그램
검사를 통과했다. 격리된 localhost 임의 포트의 실제 UDP 왕복 회귀 테스트는
상태 수신 없는 첫 송신, Q 수동 유지·재개, stale/NaN 명령 거부와 ROS 메시지
직렬화 호환성을 확인했다. 실제 MORAI 제어 송신과 closed-loop 주행은 별도 검증이다.

실행 중인 프로세스는 종료 후 이 작업 폴더의 `./run.sh`로 다시 시작해야 변경을 읽는다.
