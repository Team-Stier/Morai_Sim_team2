# 2026-10-24 Z5 주행 진단 보존본

사용자 요청으로 `Tommy_1024_Z5test` 브랜치에 현재 실행 코드와 진단 근거를
보존한다. 코드 기준은 통신 복원 커밋 `26a810f8127e32a0351a3b0fc8772807edcb96e8`이다.
이 보존 작업은 알고리즘·launch·런타임 설정을 변경하지 않는다.

## 최종 설정과 시험 범위

- 중앙 `development_localization_profile.max_dead_reckoning_sec`는 **15초**다.
- 05회차에서만 60초 비교 시험을 했고, 사용자 요청으로 설정·관련 문서·테스트를
  모두 원복했다. 60초 변경은 이 브랜치에 적용돼 있지 않다.
- 벽 정합의 기존 조건인 측정 나이 0.5초, GPS 경과 최대 60초, 수평 위치
  표준편차 3m 이하와 IMU/추정 freshness 조건은 바꾸지 않았다.
- 벽 장애물 누락과 진행방향 위치 추정 보완은 진단·제안까지 수행했으며 구현하지 않았다.
- 추가 1시간 검증 요청은 있었지만 시나리오 수정 중 사용자가 중단했다.
  이후 새 시나리오 확인과 60초 비교 회차를 수행했으며, 연속 2시간 검증을
  완료한 것으로 보고하지 않는다.

새 시나리오 SHA-256은
`117360de6d6ccec5536545b172f4cdca11ed47c86514259cba28d41b03ac0e29`다.
시나리오는 시험 배치에만 사용했고, 저장된 객체·차량 위치를 위치 추정의 관측값이나
Ground Truth로 사용하지 않았다. 추정 route 구간 변경·wrap과 음수 추정 속도는
실제 이동·완주·후진 판정에 사용하지 않았다.

## 확인된 결과

### 터널 벽이 경로 장애물 입력에서 누락됨

04회차의 실제 발행 PointPainting에 사용된 원시 LiDAR·근접 시각 영상 확률맵을
3쌍 보존해 기존 코드로 재구성했고, 실제 출력 레코드와 모두 일치했다.
LiDAR와 대응 영상의 측정시각 차이는 6.2~9.1ms였다.
15:23:59의 벽 후보 237점은 모두 영상 안에서 background로 분류되어 최종 벽점이
0점이었다. 15:24:03에는 벽 후보 4,381점 중 영상 안 1,016점이 전부 background였고,
최종 벽점이 0점이었다. 이때 GPS 경과는 각각 0.126초와 0.819초였다.
특정 측정 쌍의 직접 근거이며 모든 프레임의 전체 벽으로 일반화하지 않는다.

현재 실행은 PIDNet foreground를 사용하고, Planner는 World Model 객체점만
충돌 검사에 사용한다. 공개 HdMap에 있는 `static_obstacles`는 현재 소비하지 않으며,
`rddf_geometry_only=true`에서는 금지 경계 목록도 비어 있다.

04회차의 위치 유효 주행 trajectory 342개 발행 메시지 중 94개에서 차량 footprint와
공개 지도 벽의 occupied sample이 겹쳤다. 17개는 GPS fix가 유효한 상태였다.
이는 0.4m 패딩과 높이 차이 1.5m 이내 조건을 적용한 **지도 기준 겹침**이다.
지도 물리 정합이 미검증이므로 실제 벽 접촉·침투 깊이의 확정값은 아니다.

### 15초와 60초 비교

| 항목 | 04회차: 15초 | 05회차: 임시 60초 |
|---|---:|---:|
| 최초 LOST의 GPS 경과 | 15.009초 | 60.043초 |
| LOST 당시 모델 위치 표준편차 | 12.0m | 115.6m |

05회차는 GPS 경과 38.059초부터 최종 정지 경로를 계속 발행했다.
GPS 경과 15~60초의 실제 trajectory 발행은 주행 91개·정지 519개였다.
따라서 유효시간 연장 자체는 적용됐지만 회피 통과를 해결한 것은 아니다.
표준편차는 모델 불확실성이며 Ground Truth로 측정한 실제 위치 오차가 아니다.
LOST 이후에도 TF는 계속 발행됐으므로 TF 송신 중단으로 해석하지 않는다.

### RViz Frenet trajectory queue

저장 RViz 설정은 바꾸지 않았다. 04회차의 수동적 TF 대기 모사에서 최대 대기
marker는 6개였고, queue 5에서는 12개가 누락됐으며 queue 10에서는 누락이 없었다.
**10은 검토할 후보값**이며 실제 RViz queue A/B 시험이나 렌더링 병목 해결의
입증은 아니다. 기록 파일명의 `z5`와 별개로 해당 측정 창은 Z4 후반에서 Z5 직전까지다.

## 제안한 다음 작업 — 미구현

기본 15초를 유지하면서 Localization 내부에서 IMU 회전 보상과 LiDAR 연속 스캔의
실제 상대 이동 관측을 추가하는 방향을 제안했다. 현재 평행 벽 정합은 벽 법선 방향만
보정하므로 진행방향 드리프트를 직접 줄이지 못한다. 특징 분포·정합 잔차·겹침률과
관측 가능한 방향을 검사하고, 움직이는 객체와 퇴화 구간을 거부해야 한다.
실제 이동 관측으로 불확실성이 줄고 신선한 벽 정합 조건도 충족할 때만 기존의
조건부 벽 보조 경로를 활용하며 covariance를 임의로 낮추지 않는다.

위치 추정 개선과 별도로 터널 벽의 기하 형상을 World Model에서 보존해 Planner의
충돌 검사에 전달해야 한다. 터널 내 감속·정지·재출발·GPS 복귀와 입력 단절을
별도 검증해야 하며, 변경 전 사용자 확인을 받기로 한 범위를 유지한다.

## 변경·검증·자료 보존

- 02/03회차에서 수동 Cmd Control Connect를 눌렀고, 초기 회차에서는 로드 옵션의
  NetworkData를 해제한 조작이 있었다. 이를 코드의 자동 출발 성공과 구분한다.

  새 시나리오를 불러왔다. 04회차는 수동 Connect 없이 Connected와 출발을 확인했다.
- `i → P → ./run.sh` 시작 조건과 필요시 Q 수동 전환을 기록했다.
- 임시 60초 버전은 catkin 빌드, Localization/Architecture 패키지 테스트,
  producer-consumer 경계 검사, 중앙 다이어그램 검사와 실제 주행을 확인했다.
  15초 원복 후 기존 벽 유효성 테스트와 중앙 다이어그램 검사를 다시 통과했다.
- 원시 bag·데스크톱 영상·임시 관측 도구는 Git에 넣지 않았다. 원시 약 1.7GB는
  실행 PC의 `logs/z5_hour_20261024_142848/`에 보존했다.
- 이 폴더의 원본 증거는 byte-for-byte 복사했다. 내부의 절대 경로·당시 branch·60초
  수치는 **해당 회차의 과거 기록**이며 현재 브랜치 설정을 뜻하지 않는다.
