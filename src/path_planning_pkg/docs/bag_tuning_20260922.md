## 추가 정지 원인 수정

설정 변경 커밋 `00ca038`을 기준으로 같은 bag을 다시 조사하고 Planner 코드를
수정했다. 기존 속도·제동·충돌 거리·freshness 설정은 추가로 변경하지 않았다.

1. **이동해서 빠져나가는 물체의 현재 위치에 정지선을 만드는 문제.**
   경로 방향 속도가 0.5 m/s 이하이면 횡방향으로 움직이는 물체까지 정적으로
   처리했다. 약 454.264초에서 속도 (-0.704, -0.366) m/s인 측정 객체가 현재
   경로를 가로지르지만 시간별 충돌 검사는 통과하는데도 정지 프로파일이 나왔다.
   이제 유효한 이동 객체는 전체 객체와의 시간별 충돌 검사에 통과할 때만
   현재 위치의 공간 정지를 생략한다. 정적·속도 미확정 객체의 처리는 유지한다.
2. **막힌 committed 경로를 영구 유지하는 문제.**
   `feasible=true`는 안전한 정지 접근도 포함한다. 기존 코드는 ETA가 무한대인
   정지 경로도 committed라는 이유로 후보 검색과 선택에서 고정했다.
   이제 유한 ETA가 없는 경우 정해진 후보 평가 주기로 복귀·우회 후보를 다시
   검사한다. 유효한 유한 비용 대안이 있으면 전환하고, 없으면 기존 안전 정지
   경로를 보존한다. 단순한 비용 역전만으로 정상 committed 경로를 바꾸지 않는다.

반복 검증 도중 449.619초에서 첫 수정안의 부작용도 확인했다. 기존의 짧은
감속 경로는 안전했지만 정지 제약을 제거하면 다른 객체와 만나는 시점이 바뀌어
오히려 완전 정지가 됐다. 최종 구현은 제약 해제 경로가 충돌하면 기존 감속
접근을 다시 검사해 이 회귀를 없앴다. 이 장면과 454.264초 장면의 모든 객체
점을 `test/fixtures/crossing_stops_20260922.json`에 보존했다. 좌표 원점만
같이 평행 이동하고 1µm로 반올림했으며 객체를 제외하지 않았다.
