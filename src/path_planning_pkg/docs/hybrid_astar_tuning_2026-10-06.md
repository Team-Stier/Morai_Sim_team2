# Hybrid A* MORAI 주행 튜닝 기록 (2026-10-06)

## 범위와 기준

- 기준: `origin/main`의 `902779f`에서 새 작업 브랜치를 만들었다. 시나리오
  `2026_molit_comp_sample`을 매번 다시 로드하고 Cmd Control을 연결한 뒤
  `./run.sh`로 주행했다.
- Z2와 Z5의 Hybrid A*를 대상으로 했다. Frenet 파라미터와 Safety 코드는
  변경하지 않았다. 중앙 ROS 공개 계약도 변경하지 않았다.
- ROS의 계획 상태·후보 통계·trajectory·제어 명령·차량 속도와 MORAI 화면을
  함께 확인했다. 진단 원본은 `/tmp/hybrid_tune_run{1..7}_*`에 있다.
  이 파일들은 임시 파일이므로 재현 결과의 핵심 수치를 아래에 남긴다.

## 적용한 변경

1. `hybrid_astar.py`: 차체 네 모서리의 RDDF 통로 거리 계산을 한 번에
   수행한다. RDDF 원본 점과 차량 중심이 충분히 가까우면 삼각부등식으로
   네 모서리가 통로 안임을 확정하고 상세 계산을 생략한다. 확정되지 않으면
   기존 네 모서리 검사를 그대로 수행한다.
2. `hybrid_astar.py`: WorldModel 장애물 점을 X 좌표로 정렬하고 차량
   외접원의 X 범위에 있는 점만 기존 직사각형 충돌 검사에 전달한다.
   외접원에는 설정된 장애물 여유를 포함한다. 충돌 판정의 의미는 유지된다.
3. `path_planner_node.py`: 현재 Hybrid 경로가 무효가 되었을 때 대기 중인
   새 경로가 있으면 현재 입력·장애물·차량 자세로 다시 검사해 즉시 사용한다.
   대기 경로도 무효이면 기존 정지 동작을 유지한다. 0.5초 유지기간 종료
   시점에도 대기 경로를 재검사한다.
4. `path_planner_node.py`: 다른 callback이 새 경로를 이미 선택한 뒤
   오래된 경로 검사 결과가 그 선택을 지우지 않도록 후보 동일성과 시각을
   확인한다. Hybrid 경로 재검사 캐시의 장애물 반경을 여유가 포함된
   실제 외접원 반경으로 맞췄다.
5. `hybrid_astar.yaml`: 통로 반폭과 장애물 여유를 주행별로 비교했다.
   최종 채택값과 관찰 범위는 아래에 기록한다.

첫 실행에서 보인 309m 병목은 오프라인 재생에서도 줄었다. 저장된
305.4m 장면의 동일 112개 노드 탐색은 상세 통로 검사에서 0.618~0.719초,
빠른 승인 검사에서 0.266~0.282초였다. 309m 장면은 동일한 101점 경로와
84개 확장 노드를 유지하면서 중앙값이 0.426초에서 0.217초로 줄었다.
이는 동일 장면의 계산 비교이며 차량 주행 성공률을 증명하지 않는다.

0.5m 여유값의 4번 주행에서 Z2 정지 표본은 약 4초였다. 그러나 5번은
같은 설정으로 박스 앞에 다시 멈췄다. 4번 450m의 정지는 활성 경로와
관측 객체 사이의 물리 여유가 약 0.470m로 설정값 0.5m보다 작아진
장면에서 발생했다. 경로 재검사의 충돌 판정과 일치한다. 4번 621m의
큰 조향은 경로가 RDDF에서 약 ±0.4m 이내인 상태에서 10m 앞 경로
방향이 약 45도 바뀌는 곡선과 동반됐으며, 그때의 장애물 여유는 약 1.49m였다.

## 검증과 남은 범위

- Hybrid A* 단위 테스트 13개, Hybrid node 테스트 27개 통과.
- `catkin_make`, `./run.sh --check`, 인터페이스 다이어그램 검사,
  YAML 파싱, `git diff --check` 통과.
- 패키지 전체 단위 테스트는 137개 중 5개 실패했다. 수정하지 않은
  기준 메인의 Frenet/전환 속도 설정과 테스트 기대값 차이로,
  `world_model_input_age_sec` 기대 0.7초와 실제 1.0초 관련 2개,
  전환 속도 기대 30km/h와 실제 55km/h 관련 3개다.
  이번 작업에서 Frenet 설정과 전환 속도 코드는 변경하지 않았다.
- Z5의 실제 폐루프 주행은 위 비교에서 검증하지 못했다. Z4의 Frenet
  정지 또는 Z2 재정지 때문에 해당 구간에 도달하지 못했다.
- 이전에 저장한 Z5 1908.8m 장면 1개를 현재 코드로 오프라인 재생했다.
  현재 코드와 기준 메인 모두 동일한 102점 RDDF 경로를 만들었다.
  계산 시간은 현재 0.025초, 기존 0.045초, RDDF 최대 횡편차 0.145m,
  관측 객체와 차체의 최소 물리 여유 3.056m였다. 탐색이 필요 없는
  장면이어서 Z5 장애물 회피나 곡선 조향의 실제 주행 검증은 아니다.
- 반복 주행마다 GPS 위치 추정 재설정 횟수가 달랐다. 설정값별 진행거리와
  조향 차이를 단일 파라미터 효과로 단정할 수 없다.

`hybrid_astar.yaml`의 `corridor_half_width_m`와 `obstacle_margin_m`가
이번 비교 대상이다. **최종 로컬 값은 통로 반폭 6.0m, 장애물 여유
0.5m**로 두었다. 0.5m 조건은 Z2 완주 1회와 박스 앞 정지 1회가 있어
재현성 문제는 남아 있다. 0.6m와 0.7m는 더 넓은 여유 경로를 만들었으나
이번 폐루프 시험에서 도로 이탈·정지가 발생해 채택하지 않았다. 계산 시간
제한은 0.8초를 유지했고 Frenet 속도 파라미터는 건드리지 않았다.
