# Hybrid A* MORAI 주행 튜닝 기록 (2026-10-06)

## 범위와 기준

- 기준: `origin/main`의 `902779f`에서 새 작업 브랜치를 만들었다. 시나리오
  `2026_molit_comp_sample`을 매번 다시 로드하고 Cmd Control을 연결한 뒤
  `./run.sh`로 주행했다.
- Z2와 Z5의 Hybrid A*를 대상으로 했다. Frenet 파라미터와 Safety 코드는
  변경하지 않았다. 중앙 ROS 공개 계약도 변경하지 않았다.
- ROS의 계획 상태·후보 통계·trajectory·제어 명령·차량 속도와 MORAI 화면을
  함께 확인했다. 진단 원본은 `/tmp/hybrid_tune_run{1..7}_*`에 있다.
  이 파일들은 임시 파일이므로 재현 결과의 핵심 수치를 아래에 남긴다.

## 적용한 변경

1. `hybrid_astar.py`: 차체 네 모서리의 RDDF 통로 거리 계산을 한 번에
   수행한다. RDDF 원본 점과 차량 중심이 충분히 가까우면 삼각부등식으로
   네 모서리가 통로 안임을 확정하고 상세 계산을 생략한다. 확정되지 않으면
   기존 네 모서리 검사를 그대로 수행한다.
2. `hybrid_astar.py`: WorldModel 장애물 점을 X 좌표로 정렬하고 차량
   외접원의 X 범위에 있는 점만 기존 직사각형 충돌 검사에 전달한다.
   외접원에는 설정된 장애물 여유를 포함한다. 충돌 판정의 의미는 유지된다.
3. `path_planner_node.py`: 현재 Hybrid 경로가 무효가 되었을 때 대기 중인
   새 경로가 있으면 현재 입력·장애물·차량 자세로 다시 검사해 즉시 사용한다.
   대기 경로도 무효이면 기존 정지 동작을 유지한다. 0.5초 유지기간 종료
   시점에도 대기 경로를 재검사한다.
4. `path_planner_node.py`: 다른 callback이 새 경로를 이미 선택한 뒤
   오래된 경로 검사 결과가 그 선택을 지우지 않도록 후보 동일성과 시각을
   확인한다. Hybrid 경로 재검사 캐시의 장애물 반경을 여유가 포함된
   실제 외접원 반경으로 맞췄다.
5. `hybrid_astar.yaml`: 통로 반폭과 장애물 여유를 주행별로 비교했다.
   최종 채택값과 관찰 범위는 아래에 기록한다.

## 검증과 남은 범위

- Hybrid A* 단위 테스트 13개, Hybrid node 테스트 27개 통과.
- `catkin_make`, `./run.sh --check`, 인터페이스 다이어그램 검사,
  YAML 파싱, `git diff --check` 통과.
- 패키지 전체 단위 테스트는 137개 중 5개 실패했다. 수정하지 않은
  기준 메인의 Frenet/전환 속도 설정과 테스트 기대값 차이로,
  `world_model_input_age_sec` 기대 0.7초와 실제 1.0초 관련 2개,
  전환 속도 기대 30km/h와 실제 55km/h 관련 3개다.
  이번 작업에서 Frenet 설정과 전환 속도 코드는 변경하지 않았다.
- Z5의 실제 폐루프 주행은 위 비교에서 검증하지 못했다. Z4의 Frenet
  정지 또는 Z2 재정지 때문에 해당 구간에 도달하지 못했다.
- 이전에 저장한 Z5 1908.8m 장면 1개를 현재 코드로 오프라인 재생했다.
  현재 코드와 기준 메인 모두 동일한 102점 RDDF 경로를 만들었다.
  계산 시간은 현재 0.025초, 기존 0.045초, RDDF 최대 횡편차 0.145m,
  관측 객체와 차체의 최소 물리 여유 3.056m였다. 탐색이 필요 없는
  장면이어서 Z5 장애물 회피나 곡선 조향의 실제 주행 검증은 아니다.
- 반복 주행마다 GPS 위치 추정 재설정 횟수가 달랐다. 설정값별 진행거리와
  조향 차이를 단일 파라미터 효과로 단정할 수 없다.

`hybrid_astar.yaml`의 `corridor_half_width_m`와 `obstacle_margin_m`가
이번 비교 대상이다. **최종 로컬 값은 통로 반폭 6.0m, 장애물 여유
0.5m**로 두었다. 0.5m 조건은 Z2 완주 1회와 박스 앞 정지 1회가 있어
재현성 문제는 남아 있다. 0.6m와 0.7m는 더 넓은 여유 경로를 만들었으나
이번 폐루프 시험에서 도로 이탈·정지가 발생해 채택하지 않았다. 계산 시간
제한은 0.8초를 유지했고 Frenet 속도 파라미터는 건드리지 않았다.

## 추가 검증: 장애물 회피와 차선 근접

기존 튜닝 커밋 `e1c2acc`에서 이어서 Hybrid 파라미터만 시험했다. MORAI
`2026_molit_comp_sample`을 재로드하고 Cmd Control을 연결해 `./run.sh`로
주행했다. Planner 상태, 속도, WorldModel, 조향 명령과 차량 위치를 기록했다.
차선 여유는 HD Map 금지선에서 차량 모델의 바퀴 쪽 표본까지의 최단거리로
추정했다. 이 값은 실제 타이어 접촉이나 대회 공식 차선 판정이 아니다.

| 시험 | Z2 결과 | 판단 |
| --- | --- | --- |
| 기본값 `collision_check_step_m: 0.30`의 첫 주행 | Z2를 지나 Z5 약 1938m까지 진행했으나, 그 뒤 Route/WorldModel 입력이 무효화되어 정지 | Z2의 박스 접근 초기 기록이 없어 다른 시험과 직접 비교 불가 |
| `collision_check_step_m: 0.25` 재로드 주행 | 약 311m부터 `no_path`, 약 316m에서 정체. 금지선 근사 간격 최소 약 0.004m | 차선 여유와 재출발 문제를 해결하지 못함 |
| 기본값 `0.30` 재로드 주행 | 약 315~334m의 박스는 `success`로 통과. 약 629m에서 `time_limit` 1회 뒤 `no_path`로 정체 | Z2 전체 완주는 아님 |

0.25m 주행의 약 311m 정지 장면에서는 감지된 객체 점이 이미 Hybrid 차량
모델의 외곽 안에 있었다. 22개 정지 장면 모두 시작 자세에서 장애물 점과
차량 모델이 겹쳤다. 그래서 탐색 확장 노드가 0개, 계산 시간이 약 0.001초인
`no_path`가 반복됐다. 탐색 시간 상한을 늘리거나 충돌 검사 간격을 줄여도
이미 겹친 시작 자세를 복구하지 못한다. 이 감지점이 실제 장애물인지,
오검출인지, 위치추정 변화로 겹쳐 보인 것인지는 저장된 2D 자료만으로
확정하지 않았다.

0.30m 재주행의 약 629m 정지는 다른 형태였다. 첫 `time_limit` 뒤 차량 모델
모서리가 RDDF에서 약 7.9m 떨어져, 설정된 6m 통로 밖의 시작 자세가
됐다. 이후 장애물과 차체가 겹치지 않아도 탐색 전에 `no_path`가 났다.
통로를 8m로 넓히면 그 자세를 허용하지만, 이미 큰 RDDF 이탈을 허용하므로
차선 침범 방지라는 이번 기준에 맞지 않는다. 두 주행 모두 정지 부근에
위치추정 재설정이 있었으나 그것만을 원인으로 확정할 수 없다.

저장된 Z2 접근 장면에서 충돌 검사 간격 0.30→0.25m는 한 경로의 장애물
여유를 0.552→0.671m로 늘렸지만, 같은 경로의 금지선 근사 간격은
0.021→0.011m로 줄었다. 장애물 여유를 0.5→0.8m로 키운 다른 접근 장면은
장애물 여유가 0.515→0.943m로 늘면서 금지선 근사 간격은 0.013→0m로
줄었다. 목표 거리 30→20m는 한 `time_limit`을 해결했지만 다른 성공
장면을 `time_limit`으로 바꿨다. 충돌 검사 간격 0.25~0.32m, 통로 반폭,
장애물 여유, 목표 거리, 탐색 시간 및 합류·조향 비용도 여러 저장 장면에서
비교했으나 장애물 여유와 차선 여유를 함께 개선하는 전역 설정을 찾지 못했다.

현재 `rddf_geometry_only` 구성에서는 Hybrid에 금지선 목록이 전달되지
않으므로 Hybrid YAML 값만으로 흰색·노란색 차선을 직접 금지할 수 없다.
또한 Hybrid에는 관측 객체의 점 위치만 전달되어 동적 객체의 미래 위치를
예측하지 않는다. 따라서 이번에는 시험값을 모두 되돌리고 **기존 Hybrid
파라미터를 유지**했다. Frenet 설정, Safety, 공개 ROS 계약, 알고리즘 코드는
변경하지 않았다. 이번 재로드 주행에서 Z5까지 도달하지 못했고, 첫 주행의
Z5 입력 무효화도 원인이 확정되지 않아 Z5의 장애물 회피 성능을 검증했다고
볼 수 없다.

원복 후 `catkin_make`, Hybrid A* 단위 테스트 13개, `./run.sh --check`,
중앙 인터페이스 다이어그램 검사, YAML 파싱과 `git diff --check`가 통과했다.
