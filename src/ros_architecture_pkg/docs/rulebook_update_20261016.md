JavaScript 렌더링을 마친 공개 페이지의 본문과 표를 확인했다. 아래의 이전 값은

각 조항이 정확히 어느 날 개정됐는지는 단정하지 않는다. 페이지 표제만 보고
v1.3 등 새 버전을 만들지 않는다.

## 기존 저장소와 다른 내용

| 항목 | 기존 저장소 | 현재 공식 본문 및 반영 |
|---|---|---|
| 신호위반 패널티 | 15초 | 교차로당 30초 |
| 신호 미션 실패 | 적색 신호에서 감속 없이 미션을 건너뛰면 실패라고 기술 | 판정 대상 교차로 4개소 모두 미준수 시 해당 차시 실패로 교체 |
| 신호 중복 집계 | 명시 없음 | 동일 교차로는 1회만 집계. 체크포인트 복귀 후 재통과도 포함 |
| GPS 음영 구역 랜덤 미션 | 장애물 회피 또는 끼어들기 | 현재 목록은 장애물 회피만 명시. 일반 끼어들기 미션과 NPC 충돌 회피는 유지 |
| CP11 | 아래 이전 좌표·yaw | 10월 7일 수정안의 좌표·yaw로 갱신 |

경로·미션·체크포인트를 임의로 건너뛰면 실패한다는 일반 조항은 유지된다.
신호 조항의 교체를 다른 미션 생략 허용으로 해석하지 않는다.

### CP11 상세

좌표는 MORAI ENU, 단위 m이며 yaw 단위는 deg다.

| 값 | 이전 | 현재 공식 값 |
|---|---:|---:|
| x | 75.414203703 | 73.55110931396484 |
| y | -217.855053961 | -238.7718963623047 |
| z | 28.382283641 | 28.71942138671875 |
| yaw | -94.612335205 | -95.719757080 |

XY 이동량은 약 20.999653 m다. 다른 체크포인트와 START/END는 1e-9 m 이내의
기존 반올림 차이뿐이다. 15개 위치 및 yaw를 공식 표와 다시 대조했다.
순서와 반경 3 m는 유지된다. 중앙 `config/map/checkpoints.yaml`은 실행에 쓰는
XYZ를 소유하며 yaw는 README에 기록한다. 공개 메시지에 새 yaw 필드를 만들지 않는다.

### 이번에 문서에 추가한 운영 조항

현재 공식 §2-2-3에는 시뮬레이터 종료 등 하드웨어·소프트웨어 이슈가 발생하면
운영요원 판단으로 해당 차시를 무효로 하고 다시 주행한다고 명시돼 있다.
체크포인트 복귀의 15초 패널티와 구분한다. §2-4에는 제출 코드의 유사성 검토와
심사위원회 판단에 따른 실격 가능성이 명시돼 있다. 기존 README의 누락을 보완했으며,
이번 페이지 수정에서 새로 생긴 조항이라고 단정하지 않는다.

## 재확인한 기존 조건

- 2회 주행, 15분 제한, 출발 1분 이내 경로 5%, 체크포인트 순서와 반경 3 m.
- 일반 제한 60 km/h, 예외 구간 `A2256W000411` 시작부터 `A2256W000153` 끝까지.
- 과속 즉시 15초 및 지속 3초마다 15초, 차선 접촉·침범 지속 3초마다 5초,
  객체 충돌당 15초와 지속 접촉/재충돌 구분, 체크포인트 복귀 15초.
- 앞바퀴 정지선 통과 시점의 신호 판정, GPS blackout과 해당 구역 차로 패널티 면제.
- 차량·맵·시뮬레이터 명칭, 차량 치수, 센서 수/주기/고정 카메라 제한,
  GPS·IMU의 올해 Noise 미인가, 날씨·시간 목록.
- 허용 UDP 7종, 판정 전용 3종의 참가팀 사용 금지, cmd type 1 / ctrl mode 2,
  Competition Vehicle Status의 미제공 필드.
- PC 제출 이후 코드·실행 파라미터 수정 금지와 네트워크 설정 예외,
  실행 후 Operator 조작 금지, 일정·Client PC 사양·시뮬레이터 고정 성능 설정.

사용자 지정 일반 상한 58 km/h·고주로 목표 150 km/h는 공식 제한과 구분된
기존 중앙 코스 정책이다. 이번 공식 본문과 제한 예외 경계가 일치한다.

## 반영 범위와 실행 영향

- 루트 README: 규정 확인일, 페이지 수정 표시, 신호·랜덤 미션·운영 조항, CP11 XYZ/yaw.
- 중앙 체크포인트 YAML: CP11 XYZ, 원본 페이지 수정 표시일과 확인일.
- Architecture 및 기반 메시지 문서: 최신 근거와 이 기록 연결.
- HD Map: 중앙 XYZ를 읽어 HdMap으로 전달한다. 좌표 변경으로 map_id도 달라진다.
- Route Manager: 체크포인트 적용 모드에서 새 CP11을 목표로 사용하며 이전 CP11 위치만 통과해서는 달성되지 않는다.
  현재 기본 `route_manager.yaml`의 `rddf_geometry_only: true`는 기존 개발 모드로,
  HdMap의 체크포인트를 진행도 판정에 사용하지 않는다. 이 설정은 이번에 전환하지 않았다.
  아래 CP11 통과 회귀는 체크포인트 적용 모드의 검사다.
- RViz: 중앙 설정의 새 위치를 표시하며 표시용 평면 투영은 기존 동작을 따른다.
- Planner·Evaluator 문서: 최신 신호 채점과 랜덤 미션 범위 반영.

공식 전역경로 TXT, MGeo 원본과 `참고파일들/`은 수정하지 않는다. 기존 합류점이
이전 CP11 좌표와 같아도 도로 형상으로 남아 있으므로 새 CP11로 이동시키지 않는다.
실행 중 캐시된 지도·RouteContext·마커는 자동 교체되지 않으므로 적용 브랜치의
새 설정으로 지도·경로관리·시각화 및 관련 주행 스택을 다시 시작해야 한다.

고정 MGeo commit `fe27e92166513ac0c6c70a16d85212fc5f833fd3`와 현재 설정으로
지도를 생성해 새 CP11과 차로 폴리라인 사이의 최소 XY 거리를 검사했다.

| 차로 | 새 CP11까지 최소 XY 거리 (m) |
|---|---:|
| 원본 전역경로 | 0.001372 |
| high_speed_inner | 1.140603 |
| high_speed_outer | 1.271562 |
| high_speed_left | 2.207632 |

모두 반경 3 m 안이다. 이는 정적 형상 검사이며 실제 차량 추종 오차를 포함한
통과 보장이 아니다. 이번 변경에서 RDDF 형상을 다시 만들거나 바꾸지 않는다.

## 남은 검증 및 구현 경계

공식 판정 교차로 4개소의 운영측 식별자와 내부 지도 정지선/교차로 ID 대응은
별도 확인이 필요하다. 현재 관측 정책의 1·2·3·5번이나 신호 head 개수가
공식 판정 ID라는 뜻은 아니다. 우회전 4번 제외는 기존 사용자 설정이다.

Evaluator는 아직 미구현이다. 향후 신호위반을 추정할 때는 차시별 교차로 집합으로
중복을 제거하고, 체크포인트 복귀·Localization reset에도 같은 차시의 집합을
보존해야 한다. 다음 차시에 초기화한다. 판정 전용 UDP를 추가 구독하지 않는다.
이번 반영으로 공식 점수 계산기나 새 공개 ROS 인터페이스가 구현된 것은 아니다.

개발용 Camera3가 고정 Right Camera를 대체하는 현재 설정은 기존 문서상 본선용
검증 대기 상태다. 본선 센서 구성 검증은 계속 필요하다.

## 검증 결과

- 공식 표 대조: 15개 XYZ와 yaw 전체 일치(허용 반올림 오차 1e-9), 실제 좌표 변경 CP11 한 곳.
- HD Map 단위·계약 테스트 66개, Route Manager 3개, RViz 지도 표시 9개 통과.
- 신규 회귀: 새 XYZ가 지도에 전달되고 map_id가 갱신됨. 원본 route lane은 보존됨.
  이전 CP11에서는 통과하지 않고 새 CP11에서 CP12로 진행함.
- 중앙 다이어그램 생성 검사 통과. 중앙 테스트는 46개 중 45개 통과, 1개 실패.
  실패는 호스트 MORAI 저장 센서 파일 SHA-256 불일치이며, 수정 전 `origin/main`
  `ed7eca9`에서도 동일하게 재현했다. 이번 변경에 TF/센서 파일 수정은 없다.
- YAML 65개, launch/package XML 49개 파싱 통과.
- 변경 관련 6개 패키지의 catkin 빌드 통과.
- 실제 UDP·주행 중 callback·timestamp·TF 및 MORAI closed-loop 주행은 미수행.
